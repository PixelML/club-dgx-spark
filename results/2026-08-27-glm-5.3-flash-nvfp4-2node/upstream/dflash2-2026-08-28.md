## Outcome

PixelML reproduced the public SM121 DFlash2 vLLM port on two DGX Sparks and
served it through the local CLIProxy/OpenCodex alias. Exact response,
OpenAI tool-call JSON, code generation, and a repetition/loop guard all passed.

The headline is prompt-dependent: **61.34 decode tok/s** at 91.0% draft
acceptance for deterministic structured output, **42.55 tok/s** at 61.1%
acceptance for code-only output, and **25.28 tok/s** at 30.7% acceptance for
planning-heavy coding prompts.

## Tested configuration

- 2× NVIDIA DGX Spark, GB10 / SM121, one GPU per node.
- TP2 over the direct CX7 RoCE link.
- Target revision: `11d73216cd636238e82e1d77fe1042ffab36e7fa`.
- DFlash2 revision: `7d74cdd881ed7e32c31175984a67823127b66cfe`.
- Image digest: `sha256:4def0ef644cb2e9814136dcffd5e385e21bc594f48f3b292234051904abe85a6`.
- ModelOpt NVFP4 target weights; Marlin MoE execution; FP8 E4M3 KV.
- DFlash2 K=7; 262,144 context; `--max-num-seqs 6`.
- 3 GiB KV per rank → 310,292-token pool (1.18 full 262K requests).
- Eager execution; no CUDA graphs.

The runtime reported the expected Eagle auxiliary taps `(6,15,25,34,43)`,
FlashInfer XQA on SM121, and text-only DFlash inputs.

## What consumed time, and what fixed it

The first attempt followed the SGLang GLM cookbook's GB300-oriented support
branch onto GB10. It exposed separate SM121 gaps in NoPE attention, RoPE
attention, and FlashInfer autotune ABI handling. Each clean attempt also
reconverted the 328 GB official FP8 checkpoint to online NVFP4.

The linked Spark-specific repository supplied the missing architectural
shortcut: port DFlash2 into the already-working vLLM SM121 stack and load the
existing 194 GB NVFP4 checkpoint directly. The first launch then failed
quickly because a Hugging Face snapshot was mounted without its external
`blobs/` symlink targets. Mounting the whole HF cache fixed it.

## Caveats

- `incoai/GLM-5.3-Flash-DFlash2` is CC BY-NC-ND 4.0: evaluation only.
- The checkpoint is NVFP4, but this vLLM build reports Marlin weight-only FP4
  fallback rather than claiming native GB10 FP4 compute.
- DFlash drafting is text-only. The target's vision path is not part of this
  coding profile.
- These results do not use CUDA graphs.
- Throughput claims must include prompt shape and acceptance; “6B/18B active”
  alone does not predict decode TPS.
